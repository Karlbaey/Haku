# Archiving 功能设计文档

## 概述

为博客网站添加 Archiving 分组功能，用于存档在互联网各平台发布的帖子（如 Twitter、知乎、即刻等）。

## 核心决策

### 1. 技术架构

**实现方案：独立 Section**

```
content/
  posts/           # 原创博客
  archiving/       # 存档帖子（扁平结构）
    _index.md
    post-1.md
    post-2.md
```

**优势：**
- URL 语义清晰：`/archiving/`
- 可独立配置列表页和详情页模板
- 与 posts 明确区分

### 2. 导航集成

**位置：** 顶部导航，与 Posts、Friends 并列

**实现方式：** 在 `layouts/_partials/nav.html` 中添加自动检测代码

```go-html-template
{{ $archivingPage := $page.Site.GetPage "/archiving" }}
{{ with $archivingPage }}
  <a href="{{ .RelPermalink }}" class="site-nav-link">Archiving</a>
{{ end }}
```

**导航顺序：** 关于我 → 所有标签 → Archiving → 友情链接 → RSS

### 3. 数据结构

#### Front Matter 规范

```yaml
---
title: "帖子标题"
date: 2026-06-07              # 存档时间（用于排序）
originalDate: 2025-03-15      # 原始发布时间（用于展示）
platform: "Twitter"           # 平台名称（文本）
platformUrl: "https://..."    # 原文链接
coverImage: "/images/xxx.jpg" # 封面图（用于详情页右侧）
---

正文内容（Markdown 格式）
```

**字段说明：**
- 不使用 tags，通过 platform 字段区分
- 保留两个日期：存档时间用于排序，原始时间用于展示
- 平台信息纯文本，不使用图标
- coverImage 可选

### 4. 列表页设计 (`/archiving/`)

#### 布局结构

```
┌──────────────────────────────┐
│ Archiving                     │
│ 互联网的足迹                   │
│ Twitter (12) · 知乎 (8) · 即刻 (3) │
├──────────────────────────────┤
│ 2026-06                       │
│  ┌─────────────────────────┐ │
│  │ 帖子标题 [Twitter]       │ │
│  │ 自动截取的摘要内容...     │ │
│  │ 2025-03-15              │ │
│  └─────────────────────────┘ │
│  ┌─────────────────────────┐ │
│  │ 另一篇帖子 [知乎]        │ │
│  └─────────────────────────┘ │
│ 2026-05                       │
│  ...                          │
└──────────────────────────────┘
```

#### 关键特性

1. **头部区域：**
   - 标题：Archiving
   - 介绍语：互联网的足迹
   - 统计信息：按平台分组显示数量（Twitter (12) · 知乎 (8) · 即刻 (3)）

2. **时间线分组：**
   - 按月份倒序分组（2026-06、2026-05...）
   - 用 `date` 字段排序

3. **卡片信息：**
   - 标题后加 `[Platform]` 方括号标识
   - 自动截取正文摘要
   - 显示 `originalDate`（原始发布时间）
   - 小标签样式呈现平台标识

### 5. 详情页设计

#### 桌面端布局

```
┌─────────────────┬────────────┐
│                 │ 封面图      │
│   文章标题      │            │
│   元信息        │────────────│
│                 │ 平台卡片    │
│   正文内容      │            │
│                 │ • Twitter   │
│                 │ • 查看原文  │
│   ...           │ • 2025-3-15 │
│                 │            │
└─────────────────┴────────────┘
```

**左侧：**
- 标题
- 元信息（平台、原始发布日期）
- Markdown 正文内容

**右侧：**
- 上：coverImage（封面图）
- 下：平台信息卡片
  - 平台名称（纯文本）
  - 原始发布日期
  - 查看原文链接（整个卡片可点击跳转）

#### 移动端布局

```
┌──────────────┐
│  封面图（头部）│
│──────────────│
│  文章标题     │
│  元信息       │
│──────────────│
│  正文内容     │
│──────────────│
│  平台信息卡   │
└──────────────┘
```

封面图移到顶部，平台卡移到底部，保持垂直阅读流。

#### 平台卡片规范

- **内容：** 平台名称 + 原始发布日期
- **链接：** 整个卡片是 `platformUrl` 的跳转入口
- **样式：** 卡片式设计，点击跳转到原文
- **不包含：** 平台 logo、互动数据（点赞/转发）

#### 导航逻辑

- 不提供"上一篇/下一篇"链接（存档性质，不强调连续性）

### 6. 功能集成

#### 搜索

- 使用 Google 全站搜索
- archiving 内容被搜索引擎索引

#### RSS 订阅

- archiving 有独立的 RSS feed
- 配置在 `content/archiving/_index.md` 的 outputs 中

#### Archetype 模板

创建 `archetypes/archiving.md` 快速新建存档文章：

```yaml
---
title: "{{ replace .Name "-" " " | title }}"
date: {{ .Date }}
originalDate: 
platform: ""
platformUrl: ""
coverImage: ""
draft: true
---

```

## 设计原则

1. **内容优先：** 减少视觉干扰，聚焦正文
2. **语义清晰：** URL、导航、标识都直观易懂
3. **维护友好：** 扁平结构 + archetype，降低管理成本
4. **响应式：** 桌面/移动端都有良好体验
5. **轻量化：** 不引入额外图标资源，纯文本标识平台

## 扩展性考虑

### 未来可选功能

- 按平台筛选（在列表页增加筛选器）
- 平台专题页（`/archiving/platforms/twitter/`）
- 互动数据记录（在 front matter 添加 `likes`、`shares` 字段）
- 平台图标支持（通过配置映射 platform 名称到 SVG）

当前设计保持最小可行方案，以上功能可按需迭代。
